# E037 — conditional next GPTQ architecture (diagnostic proposal; not implementation/acceptance)

## Decision

Select one new experimental direction: **same-representation, output-tile-resident Q4 decode GEMM with register-resident FP32 K-partials and an exact ordered FP32 finalizer**, behind an experimental operator seam in `sgl-kernel/csrc/gemm/gptq/gptq_kernel.cu` and a separately named binding next to `gptq_gemm`. Do not alter default dispatch. Target S1's M≤8 native route first (initial qualification c1/c2/c4), not the M>8 reconstruct/dense route. Do not implement or re-label G017 c57, E035 FP64/packed-word, WMMA, group-serial/group-parallel or donor Marlin.

## Mechanism (new work, not coded here)

Current alt4 output CTAs reload/decode packed Q4 words and group-specific scale/zero metadata while walking K; they materialize output by K-split FP16 `atomicAdd`. Candidate prototype instead chooses an output-N tile and up to a small set of request rows, loads each packed Q4 word / its qzero+1, scale and group index once per N/K tile, and reuses those decoded values over the resident request rows. It keeps ascending K order within each of a small fixed four K partitions (no Act-order permutation), writes FP32 partials and performs a deterministic ascending-partition FP32 final reduction to the pre-cast accumulator. This changes the existing 24/96-way split/reduction geometry and therefore arithmetic association; it must pass the unchanged FP64 oracle rather than rely on presumed equivalence. No whole projection FP16 reconstruction, no all-layer offline duplicate-format pack, and no input quantization. Unlike E035 packed-word reuse, the key is **reuse decoded dequant values across M and amortize output ownership/partial merge**, not merely load four words less often in the same arithmetic. Unlike E035 group-parallel, it must not launch one CTA per group with a large all-group scratch; partition count stays small and the final order is fixed. Whether SASS actually reduces L/S instruction count or improves M=1 underutilized CTAs is unproven.

## Conditional time budget (not a measured gain)

A 5% complete-Graph Event reduction requires 1.416ms at b1, 1.576ms at b2, 1.703ms at b4. Current evidence gives only an upper envelope: candidate cannot recover more than the full GPTQ owner scope. For b4, the same Graph-node trace's GPTQ activity union is 18.536ms, but unlike-category concurrency and instrumentation boundary mean this is not subtractable wall-time; use it only as an aggressively optimistic category ceiling. For b1/b2, Eager GPTQ family sums 16.473/16.755ms are attribution scope, not Graph exclusive ceilings. There is no measured per-cell Graph GPTQ wall owner or candidate delta.

For a useful engineering screen, require the complete candidate GPTQ call to save at least the requested 5% thresholds: 1.42/1.58/1.70ms per full Forward at b1/b2/b4, with no regression in the other batch. This implies harvesting roughly 8–10% of the measured b4 GPTQ owner interval if it maps to wall time, and ~9% of the Eager b1/b2 GPTQ-family sums if they were similarly convertible; those are conditional ratios, not forecasts. **Credited guaranteed saving today: 0ms.** Plausible future range is 0–1.4/1.6/1.7ms until complete-op and matched full-Graph AB exist. Do not claim five percent from counters alone.

Expected hardware effect, if successful: reduce repeated packed-Q/zero/scale fetch/decode and long-scoreboard exposure; SM issue/active may increase. Tensor activity is not expected to improve unless a later exact-oracle-preserving tensor-core formulation passes; V100 is not being budgeted for Tensor uplift. DRAM byte reduction is limited to eliminated redundant metadata/weight transactions and must be measured; no proportionality assumed. Costs: with four partitions, whole-output FP32 scratch is `4 partitions × M × N × 4B`: at M4, 1.50MiB for merged gate_up N=24576 and 0.75MiB for down N=12288 (M1/M2 scale linearly); explicit output and reduction scratch total is 2.25MiB for the two projections in one layer but buffers are sequential/reused across layers. One deterministic reduction launch per projection and added register residency may lower occupancy. No persistent weight-format/VRAM growth; scratch pool high-water plus CUDA Graph capture retention must be measured. If scratch exceeds these formula-derived bounds, spikes past one projection at once, spills, or loses more than one resident block, stop/re-tile rather than expand memory budget. If the design needs >2MiB scratch, spills, or loses more than one block residency relative to S1, stop/re-tile rather than expand memory budget.

## Frozen numerical/quality contract and falsification

- Pre-cast FP32 output against independent FP64 GPTQ-v1 dequant/GEMM -> FP32 reference, unchanged `abs(err) <= 1e-4 + 5e-5*abs(ref)` at all six L0/L22/L43 gate_up/down fixtures and M1/M2/M3/M4 where supported; zero strict-bad, finite intermediate/final output. Test L43/down ×4 with input generated/rounded exactly as the preserved E035 forensic; c57 is already known to fail 8 positions there. The new path must pass all eight—no tolerance change, FP16-only comparison or token parity substitute.
- Also test original S1 output agreement as a diagnostic, not the mathematical authority, plus identical greedy IDs/128-token output under solo/concurrent/reuse slot lifecycle.
- Performance falsifiers: strict kernel/operator CUDA Event at exact S1 shapes fails to reduce complete projection time; Graph replay correctness fails; full Graph b1/b2/b4 median fails to save 1.416/1.576/1.703ms respectively, or service output quality/repeatability regresses; scratch >2MiB, spill/local memory appears, or M1/M2 occupancy/latency worsens materially. Stop on any strict numerical failure. This is not production authorization.

## Known unknowns

No prototype/kernel, event AB, NCU AB, full Graph AB, c1/c2/c4 service AB, prefill, memory/allocator peak or model-quality run exists. NCU counters above do not prove the proposed reuse addresses the bottleneck. b1/b2 extrapolation from b4 is uncertain. The capture-time binary SHA is not embedded in the old b4 Graph-node trace. State isolation has been directly audited separately in current S1 ModelRunner. The proposal is a single falsifiable architecture candidate only; it is not an Owner ACCEPTED optimization.
