# E035-R1 — Actual-binary local-memory diagnosis and minimal fix

## Ruling
**Root cause confirmed; R1 removes the hot local-array traffic, but `NO-GO-CANDIDATE` remains for integration.** The original 51cb cubin has dynamically-indexed `float acc[256]` in local stack space; SASS shows LDL/STL in the per-group reduction loop, distinct from register spilling. R1 replaces it with eight compile-time scalar accumulators per thread, preserving the same lane/tile map and arithmetic. R1 cubin has no LDL/STL and zero stack frame. Matched NCU DRAM write falls 313.95 MB → 0.355 MB and kernel time 2.74 ms → 526.62 µs. However whole-call Linear remains essentially unchanged versus original (M1/M2/M4 medians 973/976/1048 → 973/976/1050 µs) and is still 5.5–5.8× slower than exact c57. Therefore no GO-FORWARD, no production integration. This is a repair of E035’s local-memory bug, not evidence against the broader grouped-Q4 approach.

## Binary root-cause evidence and minimal fix
`grouped_q4_sm70.cu` pre-R1 initialized `float acc[TM*TN]` then used loop variable `t=threadIdx.x; t<TM*TN; t+=blockDim.x` to update `acc[t]` inside every GPTQ-group loop. Each lane owns only eight logical output elements, but dynamic array indexing prevented scalarization and put the whole 256-float array in the per-thread local stack.

Direct artifact inspection of actual 51cb:
- `cuobjdump --dump-resource-usage build4/e035_grouped_q4_sm70.so`: `group_wmma_fused REG:29 STACK:1024 SHARED:2048 LOCAL:0`; gather REG12 STACK0. `LOCAL:0` means no compiler-reported register spill region, but is **not** evidence against explicitly addressable stack/local array storage; STACK is 1024 bytes/thread.
- `cuobjdump --dump-sass` on the matching embedded `sm_70` cubin shows `STL [R3],RZ` for acc-array initialization, `LDL R9,[R7]` followed by `STL [R7],R8` in the group reduction loop (loop body includes `FFMA`), then a final `LDL` before output `STG`. These are actual local address-space instructions. They are not `LDG/STG` global instructions and are not shared `LDS/STS`.
- Source-to-SASS: the loop's LDL/STL pair corresponds to `acc[t]` read/modify/write for every active per-lane index in every group. Tiled B/Q global loads and activation reads remain distinct; WMMA operands use LDS/STS shared staging; final output uses STG.

R1 minimal change: retain Q4 prepack, permutation/gather, group order, WMMA, `store_matrix_sync`, per-group scale/FMA, output cast, CTA ownership and grid. Replace dynamically indexed `acc[256]` with eight scalar FP32 accumulators per lane, assigned constexpr offsets `lane + {0,32,64,96,128,160,192,224}`; each corresponding tile element is multiplied by its mapped scale and FMA'd in identical ascending-group order. Final stores use the same inverse linear index mapping. The old and R1 binaries both report REG48 for R1 vs REG29 old; R1 `STACK:0 LOCAL:0`, and SASS contains no LDL/STL. No register cap, pragma-only workaround, group reordering or other optimization was used. The converter (`convert_gptq.py`) makes group-major Q4 pack without dequantizing, retains original group->K permutation and scale row indices, and explicitly rejects qzero data not equal to the qualified fastpath. CPU converter executed on all six immutable fixture directories under `/mnt/data/pc01/sglang-v100-migration/experiments/E035/converter/`; each recorded source manifest SHA, deterministic permutation/Q/scales/zero hashes, and storage size. Then loaded the exact saved `.npy` Q4/permutation/scales into the GPU operator for all six fixtures × M1/M2/M4: 18/18 had exact Q4 reconstruction (`code_bad=0`), strict FP32 oracle bad=0, finite final FP16. Result `/mnt/data/pc01/sglang-v100-migration/experiments/E035/run4/converted-pack-correctness.jsonl`, SHA `e99bf13eca9c5b19f2a40a0661db268c0865faf233be293ac4008854056477e3`. Thus saved converter output is now verified end-to-end to the prototype call; the synthetic non-8-zero rejection and converter output metadata consistency checks remain explicit. Gate/up permutation is projection-shareable only after exact g_idx equality, while scales/qweights stay projection-specific.

## Memory accounting
Current fused per-call scratch: gather 2*M*K bytes plus a non-aliasing M*N FP32 scratch and M*N FP32 output, both caller-owned fixed buffers (return FP16 cast allocates output separately). L43 down M4 total 98,304 + 49,152 + 49,152 = 196,608 B; gate-up M4 24,576 + 393,216 + 393,216 = 811,008 B. This replaces the first prototype's unfused `G*M*N*4` FP32 partial scratch (M4 gate-up 9,437,184 B; down 4,718,592 B). For a single projection, fused output+gather pair is current scratch peak; if gate/up share permutation, they can reuse one gather scratch sequentially. Original parameter and prepacked data are not both needed at inference: prepacked Q bytes equal original packed Q bytes, transformed scale bytes same as source, permutation is 4K bytes; stored qzero metadata can be omitted only for the explicitly qualified zero=8 fastpath. Conversion peak is one layer’s old q/qzero/scales/g_idx plus new packed q/scales/permutation for that layer while repack is being made; not sum all 132 modules. Converter’s `.npy` and python NumPy intermediate host allocations are not V100 allocations. Per-module source metadata bytes from the executed saved-converter manifests: largest gate/up input metadata `39,235,584 B` and output prepack `38,940,672 B`; additional peak while that single module converts is `38,940,672 B` because old module tensors coexist until replacement, not a whole-checkpoint two-format sum. Largest down source is 19,660,800 B, output 19,513,344 B. Model total 4752 in the earlier donor report was CTA sum under a hypothetical donor geometry, not kernel-launch count; this prototype launches two kernels per call (gather+fused group WMMA) plus output-cast op when FP16 requested. No donor `a_tmp` or FP32-reduce scratch is part of this E035 path.

## R1 conclusion and next evidence-led action
**Root cause confirmed; minimum local accumulator repair verified; R1 remains NO-GO-CANDIDATE for integration.** For M4 gate_up the matched NCU evidence shows per-thread local array accesses accounted for essentially all abnormal DRAM writes and ~2.2ms of instrumented kernel latency. R1 removes those instructions/traffic and kernel time falls to 526.62µs, but complete Linear is unchanged within paired noise and still ~5.5× slower than c57. The repair does not reveal a reason to group-parallel rewrite immediately: first identify the remaining ~0.5ms gate_up / ~1.6ms down costs after R1 from the actual R1 SASS and appropriately bounded kernel sections if authorized. No change to group order, Q4 prepack, arithmetic, ownership, dispatcher, S1 or c57 was made.
