## Implementation
`grouped_q4_sm70.cu`: activation gather by deterministic stable argsort(g_idx); directly decode packed Q4, form exact FP16 integer `(q-8)` (the archived Falcon fixture audit proves every stored zero nibble=7, GPTQ-v1 effective zero=8), feed group-local 16x16x16 Volta WMMA; each CTA loops its 128-K group, FP32-accumulates the WMMA fragments, stores tile, scales group results in FP32 and accumulates groups deterministically in FP32. Final cast is only after all groups. Scratch is caller-owned fixed-shape: MxK FP16 gathered input plus MxN FP32 result; no runtime allocations in CUDA function and capture is possible. Kernel CTA grid is `[N/16, ceil(M/16), 1]` for fused kernel; actual dimensions and launched WMMA opcode remain to be verified by NCU. The converter (`convert_gptq.py`) makes group-major Q4 pack without dequantizing, retains original group->K permutation and scale row indices, and explicitly rejects qzero data not equal to the qualified fastpath. CPU converter executed on all six immutable fixture directories under `/mnt/data/pc01/sglang-v100-migration/experiments/E035/converter/`; each recorded source manifest SHA, deterministic permutation/Q/scales/zero hashes, and storage size. Then loaded the exact saved `.npy` Q4/permutation/scales into the GPU operator for all six fixtures × M1/M2/M4: 18/18 had exact Q4 reconstruction (`code_bad=0`), strict FP32 oracle bad=0, finite final FP16. Result `/mnt/data/pc01/sglang-v100-migration/experiments/E035/run4/converted-pack-correctness.jsonl`, SHA `e99bf13eca9c5b19f2a40a0661db268c0865faf233be293ac4008854056477e3`. Thus saved converter output is now verified end-to-end to the prototype call; the synthetic non-8-zero rejection and converter output metadata consistency checks remain explicit. Gate/up permutation is projection-shareable only after exact g_idx equality, while scales/qweights stay projection-specific.

## Memory accounting
Current fused per-call scratch: gather 2*M*K bytes plus a non-aliasing M*N FP32 scratch and M*N FP32 output, both caller-owned fixed buffers (return FP16 cast allocates output separately). L43 down M4 total 98,304 + 49,152 + 49,152 = 196,608 B; gate-up M4 24,576 + 393,216 + 393,216 = 811,008 B. This replaces the first prototype's unfused `G*M*N*4` FP32 partial scratch (M4 gate-up 9,437,184 B; down 4,718,592 B). For a single projection, fused output+gather pair is current scratch peak; if gate/up share permutation, they can reuse one gather scratch sequentially. Original parameter and prepacked data are not both needed at inference: prepacked Q bytes equal original packed Q bytes, transformed scale bytes same as source, permutation is 4K bytes; stored qzero metadata can be omitted only for the explicitly qualified zero=8 fastpath. Conversion peak is one layer’s old q/qzero/scales/g_idx plus new packed q/scales/permutation for that layer while repack is being made; not sum all 132 modules. Converter’s `.npy` and python NumPy intermediate host allocations are not V100 allocations. Per-module source metadata bytes from the executed saved-converter manifests: largest gate/up input metadata `39,235,584 B` and output prepack `38,940,672 B`; additional peak while that single module converts is `38,940,672 B` because old module tensors coexist until replacement, not a whole-checkpoint two-format sum. Largest down source is 19,660,800 B, output 19,513,344 B. Model total 4752 in the earlier donor report was CTA sum under a hypothetical donor geometry, not kernel-launch count; this prototype launches two kernels per call (gather+fused group WMMA) plus output-cast op when FP16 requested. No donor `a_tmp` or FP32-reduce scratch is part of this E035 path.

## Remaining / next bounded action
The completed timings plus one-kernel NCU expose the dominant defect: each output CTA (1536 CTAs for M4 gate/up) serially iterates 24 groups (down iterates 96), performs 8 WMMA K tiles per group, stores each group's 16x16 FP32 tile to shared memory, reads it back for scales and FP32 accumulation. For M4 gate/up this is 1536×24×8=294,912 WMMA ops at only one M tile, and NCU counted 4.72M tensor warp instructions, while DRAM traffic is 1,054.78 MB for the single 2.79ms kernel. The bounded NCU values make this current kernel conclusively memory/serialization dominated; arbitrary CTA tuning won't cure its algorithmic per-output CTA looping.

The E035 experiment therefore ends **NO-GO-CANDIDATE**. Do not spend more GPU/NCU effort tuning this serial-loop path. Unique next recommendation: retain the exact group-major mapping and strict-correct prototype as a reference, but any new stage must assign a CTA to (M-tile,N-tile,group) and perform deterministic FP32 scaled group reduction in a separate bounded reducer or parallel group-fusion scheme, avoiding serial 24/96-group WMMA per output CTA and large per-group DRAM materialization. That is an architectural new kernel design, not a minor tuning, so seek a new explicit scope/ownership decision before implementing another candidate. Regardless, no production dispatcher, S1 default or G017 opt-in changed, and there is no Forward/TPS/TTFT claim.
