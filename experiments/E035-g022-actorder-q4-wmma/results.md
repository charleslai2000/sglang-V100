## INFERRED
- This resolves the original “314MB write” question: a per-thread dynamically-addressed 256-float accumulator caused generated local stack array loads/stores; those actual `LDL/STL` operations were repeatedly executed per group and translated into far larger DRAM transactions. “Spill=0” alone would have been an invalid dismissal; the SASS proved local instructions and nonzero stack frame. Shared-memory `STS/LDS` WMMA staging remains on-chip and is not included in DRAM bytes.
- R1 causally removes local stack operations and almost all anomalous DRAM write traffic. It does **not** materially improve full Linear, implying that at least five-sixths of the original Linear delay remains in the gather/serial group-loop/shared-tile access/other kernel execution path. M4 gate/up alone is five times slower than exact c57 after fix; the candidate remains NO-GO.
- Exact c57 remains authoritative baseline/rollback and S1 default is unchanged.

## UNRESOLVED
- The relative contributions to the remaining R1 ~0.45ms gate/up and ~1.5–1.6ms down operation have not yet been decomposed with extra NCU attribution; this is unnecessary to reject current R1 given the c57 gap.
- No whole model Forward, production graph dispatch, service TPS/TTFT, memory-capacity, Prefill or Cache evidence. Do not make those claims.
- Requested NCU long-scoreboard metric did not return a value; no zero inference.

## Bounded answer
**Root cause: confirmed.** Original binary’s `acc[256]` lived in per-thread local stack because of dynamic indexing; its `LDL/STL` hot loop caused approximately 314 MB of DRAM writes on M4 gate/up. **Minimal repair: validated** using eight static per-thread accumulators; actual cubin has zero stack, no local load/store, same WMMA count; matching NCU cuts write bytes by 99.884% and kernel time by 80.8%. But R1 full Linear does not improve versus old and remains 5.5–5.8× slower than exact c57 on M1/M2/M4. **NO-GO-CANDIDATE** for this implementation; no Forward integration. Unique next suggestion: investigate a fused/register-owned group accumulation that eliminates remaining per-group shared-tile materialization/serial group cost, but only as a newly scoped kernel-design phase; do not start group-parallel redesign or arbitrary tune under R1 authorization.
