# E041 — G022/T007 c57 N-tile parallelism

## Question and hypothesis
At exact-c57 real Falcon L43 gate_up/down M1/M4, does changing only N tile from 128 to 64 or 32 increase independent CTAs enough to improve complete GPTQ Linear latency while preserving Q4 layout and strict numerical contract? Prediction: more CTA-level N parallelism may improve low-M GPU utilization without CTA-internal warp synchronization. A result is useful only if the complete-Linear native-FP16-c57 comparison shows at least 10% representative M4 improvement.

## Frozen object and contract
- Exact c57 partial kernel semantics reconstructed only into this isolated experiment: original Q4 `[K/8,N]` N-contiguous encoding, `g_idx`, stored qzero+1, scales, FP16 activation values; 128-K global split; same ascending split reducer; one FP32 partial plane per split; no added global splits, repacking, metadata layout changes, WMMA, FP64, Dot2, or CTA warp slicing.
- NTile128 reproduces exact c57 mapping (control): 32 lanes × 4 adjacent N outputs/lane. An NTile64/32 candidate necessarily changes lane ownership (16/8 useful lanes × 4 outputs, or 32 lanes × 2/1 outputs); it cannot preserve the original 32-lane × 4-output mapping and increase N CTA count simultaneously. E041 will explicitly test the latter coalesced alternatives (32 lanes × 2/1 outputs) as a changed lane-to-column mapping, not claim it changes only tile size. This is the smallest auditable N-direction mapping change; no K ordering/arithmetic/reduction change is intended. Arithmetic in first screen is the same sequential FP32 FMA recurrence as reconstructed c57.
- Strict pre-cast oracle remains `abs(err)<=1e-4+5e-5*abs(ref)`. A c57 strict×4 failure is a failure, never a pass. Do not alter tolerance. First screen is explicitly diagnostic: it must report whether raw FP32 outputs satisfy strict oracle before any timing; timing does not confer correctness.
- Native c57 A/B must use the production FP16-returning API, not E040's FP32-return + `.half()` path. The available `common_ops.abi3.so` only exposes the opt-in candidate API whose output can be FP32; verify the production dispatcher’s actual native-FP16 operator path and use it for A/B. If no supported isolated fixture route invokes that exact native operation, stop and report this concrete blocker rather than substitute an FP32+cast control. Complete-Linear timing includes native FP16 output cast, CTA/reducer work and matching shapes.
