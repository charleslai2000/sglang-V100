## Actual execution / donor distinction

Donor is fixed `dnv2003/v100-skinny` commit `5b589c0dc81223e0ba65bcb3e755874723f8b515`. Actual donor `skinny_nvfp4_qpn2<SPLITK,NACC>` partitions K/16 fragments across SPLITK warps, accumulates FP32, stores a small shared FP32 partial tile, synchronizes and sums partials deterministically. It is NVFP4/E4M3 group16, not GPTQ.

T010 used one warp per N32 CTA visiting all GPTQ group128s serially (for L43 K=12288, 96 groups per CTA); it was correct but ~3× slower than c57. T011's `qpn2_multiwarp.py` / generated `qpn2_multiwarp.cu` keeps E044 donor prepack, quadpair layout, FP16 integer operands, Volta HMMA, and activation gather, but distributes **whole group128s** among SPLITK warps within each N32 CTA. Each group computes a FP32 dot, applies its own original scale, writes one warp partial to bounded shared FP32 tile `[SPLITK][8][32]`; a CTA barrier and fixed warp-index FP32 sum gives output FP32 then FP16 boundary. No global G×M×N partials, atomics, FP16 partials, full FP64, or per-step weight pack. K3072 gate/up uses S8 (3 group128s per warp); K12288 down tests 8/16/32 (12/6/3 groups per warp). M<4 rows are predicated; output tile covers 8 fragment rows.
