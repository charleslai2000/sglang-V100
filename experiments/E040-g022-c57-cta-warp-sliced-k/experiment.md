# E040 — G022/T006 c57 CTA-internal warp-sliced K

## Question / falsifiable hypothesis
At exact-c57 real Falcon L43 gate_up/down M1/M4, does a 32-thread CTA with 2 or 4 warps assigned contiguous K subranges within each existing 128-K split improve eligible-warp issue / reduce dependency stalls enough to improve complete GPTQ Linear calls while preserving original Q4 layout and strict oracle? The precondition is hardware evidence that exact-c57 CTA serial K dependency is an issue/latency limiter rather than already saturated math/DRAM or an occupancy ceiling. Falsify before implementation if counters show no plausible independent latency to expose or resource occupancy already precludes benefit.

## Frozen implementation contract
- Original GPTQ checkpoint storage / Q4 `[K/8,N]`, N-contiguous; original g_idx, stored qzero+1 semantics, scales and FP16 activation values.
- Same N mapping (32 threads, 4 N outputs/thread), M1–4 and original global K partition size 128. Each CTA still writes one FP32 partial at the existing `[split,M,N]` address; no increase to global split planes or interface.
- CTA-internal 2/4 warps handle contiguous K strips. Each warp computes FP32 FMA subsequence; fixed-order CTA reduction writes one partial. The reduction association differs from c57 and must satisfy strict oracle.
- Final c57 reducer remains ascending FP32 sum unless a measured numerical failure justifies deterministic Kahan; no precision relaxation.
